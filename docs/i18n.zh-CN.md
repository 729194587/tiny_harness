# 双语文档维护

[English](i18n.md) | [简体中文](i18n.zh-CN.md)

每篇维护中的文档都有三个同目录文件：英文 `foo.md`、简体中文 `foo.zh-CN.md`，
以及审阅记录 `foo.i18n.yaml`。两种语言具有同等效力。记录表示两份文件的这些具体内容
已被共同审阅；哈希匹配并不能证明它们语义一致。

## 维护范围

`scripts/i18n.py` 检查仓库根目录下的 Markdown，并递归检查 `docs/` 和
`evals/swe_bench_lite/`。这些位置的新增文档也必须有两种语言和审阅记录。
根 README、Runtime 说明、上下文归因说明和评测 README 是必需文档，即使三个同名文件
全部被删除，检查仍会报错。本维护指南也属于双语文档。

操作指令 `AGENTS.md`、`SKILL.md` 及其中文版本，以及 `docs/superpowers/plans/`
下的历史计划不在维护范围内。其他目录，包括内置技能和生成结果所在的 `evals/results/`，
也不纳入本阶段。范围外的记录不会被检查；范围内缺少对应文档的记录、未知字段和重复字段
都会导致校验失败。

## 修改、审阅与记录

1. 可以先修改任一语言，再同步另一种语言，保留相同的事实、约束和不确定性。
   按意思组织译文，不照搬句式；使用自然的技术中文，保持术语一致。代码标识符、命令和
   API 名称保持原样。描述构建工具的函数时，直接说明函数的行为，不称为“工厂”。
2. 分别独立阅读两种语言，再逐项比较，检查示例、链接、限制和断言的确定程度。
   句式和分段可以不同，语义一致性由人工审阅负责。
3. 审阅完成后，显式记录该文档对，再检查全部记录：

   ```powershell
   python scripts/i18n.py record docs/runtime
   python scripts/i18n.py check
   ```

按常规方式安装项目（`python -m pip install -e .`）后，在仓库根目录运行这些命令；
脚本使用已有的 PyYAML 依赖。`record` 接受相对于仓库的文档对路径，也可以带英文文件的
扩展名，例如 `docs/runtime.md`。两种语言文件必须都存在；命令只写入这一对的记录，
审阅后也可以用它替换格式错误的记录。它不会翻译或协调内容，也没有批量记录命令。

`check` 始终只读。文件缺失、记录缺失或无效、正文与记录不符时，命令返回非零退出码，
并指出英文、中文还是两者都发生了变化。即使两种语言都改了，也必须共同审阅并显式重新记录；
同时修改不代表已经确认一致。离线 CI 只运行 `check`。

## 记录格式与局限

记录只包含 `en_sha256` 和 `zh_CN_sha256`，各自是对应文件全部字节的 SHA-256，
使用长度为 64 的小写十六进制字符串。未知字段、重复字段和其他 YAML 结构都会被拒绝。
`.gitattributes` 将 Markdown 的检出换行符固定为 LF，使 Windows 和 Linux 计算相同的
文件字节。请让编辑器保留 LF；空白变化也会使记录失效。

检查器不会验证翻译、Markdown 链接、术语或文档结构，也无法证明审阅实际发生过。
它不保存审阅人身份或历史正文；需要比较上次审阅版本时，请查阅 Git 历史。
不要仅仅为了让 CI 通过就刷新哈希。
