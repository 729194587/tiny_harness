# Maintaining bilingual documentation

[English](i18n.md) | [简体中文](i18n.zh-CN.md)

Each maintained document has three sibling files: `foo.md` (English),
`foo.zh-CN.md` (Simplified Chinese), and `foo.i18n.yaml` (review record).
Both languages are equally authoritative. A record says their exact contents
were reviewed together; matching hashes cannot prove that the meanings agree.

## Scope

`scripts/i18n.py` discovers Markdown files directly in the repository root and
recursively under `docs/` and `evals/swe_bench_lite/`. New documents in these
locations need both languages and a record. The root README, runtime reference,
context-attribution reference, and evaluation README are required even if all
three sibling files are removed. This guide is also a maintained pair.

Operational `AGENTS.md` / `SKILL.md` files (and their Chinese counterparts) and
historical plans under `docs/superpowers/plans/` are excluded. Other directories,
including bundled skills and generated `evals/results/`, are outside this initial
scope. Records outside the scope are not inspected. Within it, orphan records,
unknown record fields, and duplicate fields fail verification.

## Edit, review, record

1. Edit either language and update the other to preserve the same facts,
   constraints, and uncertainty. Translate meaning, not sentence structure;
   use natural technical Chinese and consistent terminology. Keep code
   identifiers, commands, and API names unchanged. Describe tool-building
   functions as functions, not “工厂”.
2. Read each version independently, then compare them. Check examples, links,
   limitations, and the strength of claims. Different sentence and paragraph
   structures are fine. Human review owns semantic consistency.
3. After that review, explicitly record the pair and check all records:

   ```powershell
   python scripts/i18n.py record docs/runtime
   python scripts/i18n.py check
   ```

Run these commands from the repository root after the normal project install
(`python -m pip install -e .`); the script uses the existing PyYAML dependency.
`record` accepts a repository-relative pair stem or English filename, such as
`docs/runtime.md`. It requires both files, writes only that pair's record, and
can replace a malformed record after review. It does not translate or reconcile
content. There is no bulk recording command.

`check` never writes files. It exits nonzero for missing files, missing or invalid
records, or changed content, reporting English, Chinese, or both as changed.
Even if both languages changed, review and explicit re-recording are required;
editing both files is not automatic confirmation. Offline CI runs only `check`.

## Record format and limits

Records contain exactly `en_sha256` and `zh_CN_sha256`, each a lowercase,
64-character SHA-256 digest of the corresponding file's full bytes. Unknown
keys, duplicate keys, and other YAML shapes are rejected. `.gitattributes`
keeps Markdown checkouts in LF form so Windows and Linux hash the same bytes.
Configure editors to retain LF; changing whitespace also invalidates a record.

The checker does not validate translations, Markdown links, terminology, or
document structure. It cannot prove that review happened, and does not retain
reviewer identities or earlier contents. Use Git history to compare against the
last reviewed revision. Never refresh hashes just to make CI pass.
